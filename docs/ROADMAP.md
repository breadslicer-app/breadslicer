# Direction and decisions

Tasks live in the [issues](https://github.com/breadslicer-app/breadslicer/issues), and the current order of work lives in the pinned "Work order" issue. This file holds only the decisions that guide development.

## The main goal (Damian, 2026-10-30)

**Breadslicer's main milestone is to be the best slicer there is**: in ease of use, speed, optimization and responsiveness, in everything.

- **Everything that can be optimized gets optimized, even if it only saves milliseconds.** A faster frame, a shorter wait, one less step: each one counts.
- **The one limit is the user's file.** No optimization may risk what gets printed: the layers, the supports, the hollow and the saved project come out the same or better, and that is proven (byte-identical output or a measured comparison) before it lands.
- When there is a choice between "good enough" and "the best", we pick the best and log it as an issue if it cannot be done right away.

## Decisions (Damian, 2026-10-26)

- **The best slicing experience there is**, not "yet another slicer".
  - Everything has to feel smooth and immediate.
  - Missing printers or details is acceptable; a mediocre experience is not.
- **No inherited algorithm is untouchable.** What works well stays. But when there is a real improvement, we make it, even if it changes previous behavior.
- **Structural rules come from physics, not from fixed limits.**
  - Example: a cap on members per trunk makes no sense if the trunk is already braced and anchored to the model in earlier layers.
  - The actual load is decided by structural analysis (BS-11).
- **Structural analysis:** per-layer forces plus a beam model of the support tree, on the critical layers. 3D tetrahedral FEA is reserved for fine model details, and comes later.
- **Two-level calibration:**
  - a single-plate "quick check";
  - a 3–4 plate "proper calibration".

  All test pieces are our own, generated by code (BS-78, BS-79). Reading results from a photo comes later, with machine learning.
- **Pre-supported STLs (BS-77):** they are split into bodies, and supports are recognized and can be deleted. Being able to "keep only this object".
- **Brand:** Breadslicer (`breadslicer.app`).
  - The rename touches only what is visible and migrates user data (BS-75).
  - Internal code names (`sc-*`) do not change.
- **Licenses:** the project is AGPL-3.0. The license and authorship notices of the code we started from are always kept, and the acknowledgement goes at the bottom of the README.
